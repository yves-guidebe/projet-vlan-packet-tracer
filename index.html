Projet phare : réseau d'entreprise segmenté

Simulation sous Cisco Packet Tracer d'un réseau à deux services : la Direction (VLAN 10) et les Ressources humaines (VLAN 20). Objectifs : isoler les services, les faire communiquer par un routeur, distribuer les adresses automatiquement, sécuriser l'administration par SSH et interdire la communication entre deux postes précis (PC1 vers PC4).

  • 1 routeur 2911 (r1)
  • 2 switches 2960 (sw1, sw2)
  • 4 postes
  • 2 VLAN

Configuration

Switch (exemple : sw1)

vlan 10
 name dir
vlan 20
 name rh
interface fa0/1
 switchport mode trunk
interface fa0/2
 switchport mode access
 switchport access vlan 10
interface fa0/3
 switchport mode access
 switchport access vlan 20

sw2 : mêmes VLAN, trunks sur Fa0/1 et Fa0/2, poste du VLAN 10 sur Fa0/3 et poste du VLAN 20 sur Fa0/4.

Routeur : routage inter-VLAN (router-on-a-stick)

interface g0/0
 no shutdown
interface g0/0.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
interface g0/0.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0

DHCP (un pool par VLAN)

ip dhcp pool VLAN10
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
ip dhcp pool VLAN20
 network 192.168.20.0 255.255.255.0
 default-router 192.168.20.1

SSH (administration sécurisée du switch)

interface vlan 10
 ip address 192.168.10.5 255.255.255.0
 no shutdown
ip default-gateway 192.168.10.1
ip domain-name exemple.local
username admin secret ********
crypto key generate rsa modulus 2048
ip ssh version 2
line vty 0 4
 login local
 transport input ssh

ACL : interdire PC1 vers PC4

Posée en entrée sur la sous-interface du VLAN 10, point de passage obligatoire vers le VLAN 20.

ip access-list extended bloquer-pc1-pc4
 10 deny ip host 192.168.10.2 host 192.168.20.2
 20 permit ip any any
interface g0/0.10
 ip access-group bloquer-pc1-pc4 in

Dépannage

PasserellePostes sans communication inter-VLAN

Constat : une passerelle différente avait été saisie sur chaque switch.
Cause : un switch de couche 2 n'est pas la passerelle des postes.
Solution : tous les postes d'un VLAN utilisent la même passerelle, l'adresse de la sous-interface du routeur.

ACLRègle visant la mauvaise adresse

Constat : l'ACL ne protégeait pas le bon poste.
Cause : la règle ciblait 192.168.20.3, or le DHCP avait attribué cette adresse à PC2 et 192.168.20.2 à PC4.
Solution : règle réécrite avec l'adresse relevée par ipconfig sur PC4. Piste d'amélioration : adresses statiques pour les postes concernés.

ACLPlus d'adresse DHCP dans le VLAN 10

Constat : PC1 et PC3 n'obtenaient plus d'adresse.
Cause : l'ACL ne contenait qu'une ligne deny. Le deny any implicite bloquait tout le reste du VLAN 10, demandes DHCP comprises.
Solution : ajout de 20 permit ip any any, puis renouvellement de l'adresse sur les postes.

IOSErreurs « Invalid input detected »

Constat : des commandes d'ACL étaient rejetées.
Causes : faute de frappe (acces-list), mot-clé manquant (permit any any au lieu de permit ip any any), plusieurs commandes saisies sur une seule ligne.
Solution : une commande par ligne, en vérifiant que l'invite passe en config-ext-nacl, et lecture du marqueur ^ qui pointe l'erreur.
